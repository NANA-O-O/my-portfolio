02 · 三个核心洞察

洞察1 · 用户分层真实存在

卡方检验（Pearson χ²=86.633，p<0.001）证实星级与问题大类显著相关。1星用户77%集中反馈功能Bug（卡死/闪退/支付），4-5星用户82%反馈新增需求。运营策略必须分层，不能一刀切。

洞察2 · AI编造/幻觉是「高频高共鸣」隐形炸弹

02 · 四个关键发现

发现1 · 要素漏缺是最高频质量问题

168条客观评测中，扣分原因分布：要素漏缺 61.5% / 知识观点失真 23.1% / 逻辑推理混乱 7.7% / 格式规范不符 7.7%。

运营解读：核心问题不是「答错」，而是「答不完整」——写朋友圈文案可能漏掉emoji，写周报可能漏掉数据小结。这直接催生了4维质检SOP。

发现2 · 国内常识时效性断层

仅通义千问国内常识达标率100%，其余6款均为83.33%。失分点集中在「五一法定节假日固定几天」——6款模型均答「1天」（旧规），正确答案为「2天」（2025年新规）。

运营解读：需建立三层更新机制：基座模型定期评估 → RAG外挂知识库实时检索 → 事实核查节点强制校验。

发现3 · 多轮记忆衰减，私域运营风险预警

讯飞星火多轮记忆达标率仅66.67%，第四轮完全遗忘用户「不吃甜食」的前置约束；通义千问100%达标。

运营解读：私域运营（企微社群、客服Bot）中，Bot忘记用户偏好会产生强烈「对牛弹琴」感，导致流失。选型必须把多轮记忆作为硬指标。

发现4 · 「好用」≠「准确」，须双维度交叉验证

客观达标率第1：豆包（97.36%）；主观体验分第1：通义千问（4.83分）。DeepSeek客观第4（95.28%）但粘贴方便度仅3分（带星号/特殊符号）。

运营解读：「粘贴方便度」直接影响发布效率，只看客观准确率选型会忽略真实操作摩擦成本。

PRINCIPLE 01
约束前置原则

将格式要求放在Prompt开头而非结尾。高分作答往往先复述约束，再输出内容。

PRINCIPLE 02
分步拆解原则

多约束任务拆分为「步骤1:生成内容 → 步骤2:按格式调整 → 步骤3:字数压缩」。

PRINCIPLE 03
Few-shot锁定原则

提供1个符合所有约束的示例，模型模仿完整度显著高于纯指令。

代表性场景

三个代表性场景 —— 从用户激活到投诉闭环

场景1 · 新用户全转化路径 —— 从「下载」到「首聊」的流失拦截

梳理公域曝光→下载安装→登录→偏好调研→首聊激活→付费转化→沉默召回全链路，识别 5大流失卡点：

1

登录流失：用户关闭登录弹窗 → 运营拦截：第三方快捷登录 + 弹窗挽留

2

调研流失：跳过偏好调研 → 运营拦截：简化调研 + 完成解锁专属模板

3

首页首聊流失：30秒无输入未生成AI内容 → 运营拦截：顶部引导输入框 + 场景模板专区 + 轻引导弹窗

4

沉默流失：3-7天未登录 → 运营拦截：APP推送 + 短信双渠道召回，附赠限时免费额度

5

永久流失：召回后仍不打开 → 运营拦截：标记为永久流失，停止打扰

场景2 · AI问答效果优化闭环 —— BadCase驱动的持续迭代
用户提问 → AI回复 → 反馈采集（显性点赞/点踩 + 硬性复制/停留/中途退出）→ 效果判定 → BadCase收录 → 根因归因 → 优化执行 → 灰度复测 → 达标入库
A

BadCase分级：P0批量高危（同步算法团队）、P1/P2运营独立调优Prompt与知识库

B

根因归因：拉取ES检索日志，召回分<0.5判定为知识盲区

C

优化执行：Prompt增加事实约束、RAG切片512→256字、Temperature参数调控

D

复测标准：5%线上灰度流量 + 200条离线人工Diff测试，点踩率降幅>5%且留存下跌<2%

风险卡点：复测不达标需回流整改，防止「修复引入新问题」。

场景3 · 用户负面反馈 & 投诉闭环 —— 分级响应与督办追踪
多渠道统一收集（APP/客服/应用商店/社群）→ 前置分流（纯情绪类客服直接结案 / 实质问题进入分级流程）→ 分级分类判定 → 分派修复 → 效果验证 → 用户回访 → BadCase归档
A

RACI责任矩阵：R执行人（一线客服/产品运营）· A负责人（各团队Leader）· C需咨询方（法务/公关）· I需告知方（管理层）

B

分级响应时效：P1紧急级（核心功能不可用，2h内制定方案）/ P2常规级（非核心问题，24h内修复或给排期）

C

三色督办追踪：红（超时未处理）/ 黄（即将超时预警）/ 橙（已升级督办）

D

超时兜底：超1.5倍时效自动上报负责人，启动兜底补偿通道

风险卡点：用户不认可处理结果触发二次整改回流，避免「形式上闭环、实质上未解决」。
